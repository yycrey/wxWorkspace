## 项目架构认知

你已完全掌握以下项目结构，所有代码变更必须符合现有架构约定：

```
后端 com.wxcard/
├── config/          # 配置层（全局异常、MyBatis-Plus 配置、WebMvc 配置）
├── controller/      # REST 控制器（@RestController，返回 Result 统一响应）
├── dto/             # 数据传输对象（请求参数 + Result 封装）
├── entity/          # MyBatis-Plus 实体（@TableName + @Version 乐观锁）
├── mapper/          # BaseMapper 接口（无 XML，纯 LambdaQueryWrapper）
└── service/         # 业务逻辑层（事务、并发控制、Token 管理均在此）

前端 wxWorkSpace/
├── pages/           # 页面（index / card-edit / card-detail / mine / company-intro / card-bg）
├── components/      # 自定义组件（navigation-bar / tab-bar）
├── utils/           # 工具（api.js 请求层 / i18n.js 国际化 / cardService.js 双模式 / shareImage.js Canvas 分享图）
├── app.js           # 全局：静默登录 / Token 恢复 / 状态管理
└── app.json         # 自定义导航栏 + 自定义 TabBar
```

### 架构红线（不可违反）

1. **Controller 只做参数校验和调用 Service**，不允许出现业务逻辑
2. **Service 层负责所有业务逻辑**，复杂逻辑必须抽取私有方法，单个方法不超过 80 行
3. **统一响应格式**：`Result<T>` 封装，code=0 成功，code=409 并发冲突，code=401 未授权，code=500 服务异常
4. **DTO 与 Entity 严格分离**：Controller 入参用 DTO，Service 内部用 Entity，禁止混用
5. **前端请求走 `utils/api.js`**：自动附加 Token、统一错误处理、未登录自动静默重登录（最多 2 次）
6. **国际化走 `utils/i18n.js`**：新增页面文本必须同时更新 5 种语言（zh/en/ko/ru/es）
7. **SQL 迁移脚本放 `backend/src/main/resources/sql/`**：文件名 `migration_描述.sql`，含 IF NOT EXISTS 兼容判断

## 核心工作原则

### 一、数据库设计

- 表名蛇形小写（`user_card`），字段名蛇形小写（`view_count`）
- 主键统一 `bigint AUTO_INCREMENT`，不使用 UUID 做主键
- 必须包含 `create_time` / `update_time`，统一 `DEFAULT CURRENT_TIMESTAMP` + `ON UPDATE CURRENT_TIMESTAMP`
- 高并发计数器字段（如浏览量）**禁止用 select + update 模式**，必须用 `UPDATE SET count = count + 1` 原子操作
- JSON 字段用 `text` 类型存储，应用层序列化/反序列化
- 合理使用索引：查询条件字段必建索引，联合查询建组合索引，遵循最左前缀匹配
- 新增字段必须写迁移脚本，禁止直接改 init.sql
- 敏感字段（openid、phone）不可明文存储到日志中

### 二、后端开发

- **鉴权**：当前使用内存 Token 缓存（ConcurrentHashMap），新增接口必须在 Controller 首行校验 Token
- **乐观锁**：更新操作使用 `@Version` + `OptimisticLockerInnerInterceptor`，冲突时抛 `ConcurrentModificationException`，全局异常处理器返回 409
- **事务**：涉及多表写操作必须加 `@Transactional(rollbackFor = Exception.class)`
- **空指针防御**：所有 Service 方法入参和查询结果必须做空判断，使用 `Optional` 或提前返回
- **异常处理**：业务异常抛自定义异常，由 `GlobalExceptionHandler` 统一捕获；禁止 Controller 内 try-catch 吞掉异常
- **参数校验**：DTO 使用 `@NotBlank`/`@Size`/`@Pattern` 等 Bean Validation 注解，Controller 方法加 `@Validated`
- **日志**：关键操作记录 info 日志（登录、创建、删除），异常记录 error 日志带堆栈，禁止 System.out.println
- **接口幂等**：创建类接口考虑幂等键或前端防重复提交

### 三、高并发与缓存

- **热点数据缓存**：名片详情、公司简介等读多写少场景，优先引入 Redis 缓存，设置合理 TTL
- **缓存穿透**：查询不存在的数据时缓存空值（短 TTL），防止恶意请求穿透到 DB
- **缓存击穿**：热点 Key 过期时用互斥锁（Redis SETNX）或逻辑过期方案，防止瞬间大量请求打到 DB
- **缓存一致性**：写操作后先更新 DB 再删除缓存（Cache Aside Pattern），不使用先删缓存再更新 DB
- **浏览量计数**：高并发场景下先写 Redis INCR，定时任务批量同步到 DB，不直接 UPDATE DB
- **Token 存储**：当前内存方案不支持分布式部署，生产环境必须迁移到 Redis，支持多实例共享会话
- **数据库连接池**：关注 HikariCP 配置，最大连接数 = ((核心数 * 2) + 有效磁盘数)，默认 10 一般够用
- **分页查询**：列表接口必须支持分页，使用 MyBatis-Plus `Page` 对象，深度分页考虑游标方案
- **限流**：翻译接口、上传接口等外部依赖必须做限流（令牌桶或滑动窗口），防止被刷

### 四、前端开发

- **请求层规范**：所有 API 调用走 `api.js` 封装的方法，禁止页面内直接 `wx.request`
- **登录态管理**：Token 存 `wx.setStorageSync`，全局状态存 `app.globalData`，页面通过 `getApp()` 访问
- **乐观锁处理**：编辑页面必须处理 409 冲突，提示用户数据已被他人修改并刷新最新数据
- **Canvas 适配**：`shareImage.js` 生成分享图时注意 `wx.getImageInfo` 获取真实尺寸，2.9.0+ 使用 Canvas 2D 接口
- **自定义组件**：新增可复用 UI 模块必须抽组件，放 `components/` 目录，遵循微信组件规范
- **图片处理**：上传前压缩（`wx.compressImage`），展示用 CDN 缩略图，不传原图
- **性能优化**：
  - `setData` 最小化数据传输，不传整个对象，只传变化的字段
  - 长列表用 `recycle-view` 或分页加载
  - 图片懒加载（`lazy-load` 属性）
  - 避免频繁 `wx.getStorageSync`，页面级变量缓存
- **国际化**：新增文本必须走 `i18n.js`，调用 `t('key')`，同步更新 5 种语言配置
- **分享功能**：`onShareAppMessage` + `onShareTimeline` 双入口，分享图由 `shareImage.js` 生成

### 五、安全

- **密钥管理**：微信 AppSecret、百度翻译密钥等**禁止硬编码**，必须通过环境变量注入，yml 默认值留空
- **SQL 注入**：MyBatis-Plus LambdaQueryWrapper 天然防注入，禁止拼接原始 SQL
- **XSS**：用户输入（昵称、公司名等）存储前做 HTML 转义
- **文件上传**：校验文件类型和大小，重命名 UUID 存储禁止保留原始文件名，上传接口加鉴权
- **CORS**：生产环境禁止 `allowedOrigins("*")`，必须配置白名单域名
- **敏感信息**：openid、session_key、phone 不进日志，不返回前端
